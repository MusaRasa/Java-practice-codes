# Java Programming

Java is a high-level,
object-oriented programming language.

It was designed to be portable,
reliable, and suitable for building
large-scale software systems.

Java programs are compiled into bytecode.

The bytecode runs on the Java Virtual Machine.

This allows Java applications
to run on different operating systems
without changing the original source code.

The main idea is often described as:

"Write Once, Run Anywhere."

---

# Java Development Kit

The Java Development Kit,
or JDK, provides tools required
to develop Java applications.

The JDK contains the Java compiler,
runtime tools, and development utilities.

The Java compiler converts Java source code
into bytecode.

The Java source file normally uses
the `.java` extension.

After compilation,
the generated bytecode uses
the `.class` extension.

---

# Basic Java Program

A basic Java program contains
a class and a main method.

The main method is the entry point
of a traditional Java application.

Example:

```java
public class Main {

    public static void main(String[] args) {
        System.out.println("Hello Java");
    }
}
```

The `class` keyword defines a class.

The `main` method starts program execution.

`System.out.println()` prints information
to the console.

# Variables

A variable is a named memory location
used to store a value.

Example:

```java
int age = 22;
double price = 150.5;
String name = "Mosa";
```

The variable type determines
what kind of value can be stored.

Variables make programs dynamic
and allow data to be processed.

# Object-Oriented Programming

Object-Oriented Programming,
commonly called OOP,
is a programming paradigm.

OOP organizes software around objects.

An object represents an entity
with data and behavior.

Data is commonly represented
using fields.

Behavior is represented
using methods.

---

# Classes

A class is a blueprint
for creating objects.

Example:

```java
class Student {

    String name;
    int age;

    void study() {
        System.out.println("Student is studying");
    }
}
```

The class defines
what an object will contain.

A class can contain:

* Fields
* Methods
* Constructors
* Nested classes

---

# Objects

An object is an instance of a class.

Example:

```java
Student student = new Student();
```

The `new` keyword creates
an object in memory.

The object can access
the members defined by its class.

Example:

```java
student.name = "Mosa";
student.age = 22;
student.study();
```

---

# Constructors

A constructor is a special member
used to initialize objects.

Example:

```java
class Student {

    String name;

    Student(String name) {
        this.name = name;
    }
}
```

An object can then be created with:

```java
Student student = new Student("Mosa");
```

Constructors have the same name
as their class.

They do not have a return type.

---

# The `this` Keyword

The `this` keyword refers
to the current object.

Example:

```java
class Student {

    String name;

    Student(String name) {
        this.name = name;
    }
}
```

Here, `this.name`
refers to the object's field.

The parameter `name`
refers to the constructor parameter.

---

# Encapsulation

Encapsulation is one
of the fundamental principles of OOP.

It means keeping an object's internal state
protected from uncontrolled access.

Fields are commonly declared private.

Access is then provided through methods.

Example:

```java
class BankAccount {

    private double balance;

    public double getBalance() {
        return balance;
    }

    public void deposit(double amount) {
        balance += amount;
    }
}
```

Encapsulation improves data protection.

It also gives the class
control over how its data changes.

---

# Getters and Setters

A getter is used to retrieve
the value of a field.

A setter is used to modify
the value of a field.

Example:

```java
public String getName() {
    return name;
}

public void setName(String name) {
    this.name = name;
}
```

Getters and setters can also
contain validation logic.

---

# Access Modifiers

Java provides access modifiers
for controlling visibility.

Important access modifiers include:

* public
* private
* protected
* default

`public` members can be accessed
from other classes.

`private` members are accessible
only inside their declaring class.

`protected` provides controlled access
through inheritance and package rules.

---

# Inheritance

Inheritance allows one class
to acquire properties and behavior
from another class.

The parent class is also called
a superclass.

The child class is also called
a subclass.

Example:

```java
class Animal {

    void eat() {
        System.out.println("Eating");
    }
}

class Dog extends Animal {

    void bark() {
        System.out.println("Barking");
    }
}
```

Dog inherits the `eat()` method
from Animal.

---

# Why Use Inheritance?

Inheritance can reduce code duplication.

It can also represent
an "is-a" relationship.

For example:

Dog is an Animal.

Car is a Vehicle.

Teacher is a Person.

However, inheritance should be used
when the relationship is logically appropriate.

---

# Method Overriding

Method overriding occurs
when a subclass provides
its own implementation
of a superclass method.

Example:

```java
class Animal {

    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Bark");
    }
}
```

The subclass changes
the behavior inherited from the parent.

---

# Polymorphism

Polymorphism means
"many forms."

It allows one interface
or reference type
to represent different objects.

Example:

```java
Animal animal = new Dog();
animal.sound();
```

Although the reference type
is Animal,
the actual object is Dog.

The Dog implementation
of `sound()` is executed.

---

# Runtime Polymorphism

Runtime polymorphism is commonly achieved
through method overriding.

The method that executes
can depend on the actual object
at runtime.

This makes programs
more flexible and extensible.

It is an important concept
in object-oriented design.

---

# Method Overloading

Method overloading means
having multiple methods
with the same name
but different parameter lists.

Example:

```java
int add(int a, int b) {
    return a + b;
}

double add(double a, double b) {
    return a + b;
}
```

The compiler determines
which method should be called.

---

# Overloading vs Overriding

Overloading happens
within a class or inheritance hierarchy
with different parameter lists.

Overriding occurs when a subclass
redefines an inherited method.

Overloading is mainly associated
with compile-time polymorphism.

Overriding is associated
with runtime polymorphism.

---

# Abstraction

Abstraction means
hiding unnecessary implementation details
and exposing essential behavior.

For example,
a user can call:

```java
car.start();
```

without knowing every internal operation
required to start the engine.

Abstraction reduces unnecessary complexity.

---

# Abstract Classes

An abstract class
cannot normally be instantiated directly.

It can contain abstract methods
and concrete methods.

Example:

```java
abstract class Animal {

    abstract void sound();

    void sleep() {
        System.out.println("Sleeping");
    }
}
```

A subclass must implement
the required abstract methods.

---

# Interfaces

An interface defines
a contract that classes can implement.

Example:

```java
interface Flyable {

    void fly();
}
```

A class can implement it:

```java
class Bird implements Flyable {

    public void fly() {
        System.out.println("Flying");
    }
}
```

Interfaces are useful
for defining common behavior.

---

# Abstract Class vs Interface

An abstract class can contain
state and implemented behavior.

An interface primarily defines
a contract for behavior.

A class can extend one class.

A class can implement multiple interfaces.

Interfaces are useful
when unrelated classes
need to share a common capability.

---

# Composition

Composition represents
a "has-a" relationship.

Example:

A Car has an Engine.

Instead of inheriting from Engine,
the Car can contain an Engine object.

Example:

```java
class Car {

    private Engine engine;

    Car() {
        engine = new Engine();
    }
}
```

Composition is often preferred
when inheritance does not represent
a true "is-a" relationship.

---

# Association

Association describes
a relationship between objects.

For example:

A Teacher teaches Students.

A Customer places Orders.

Objects can interact
without one necessarily owning
the lifetime of the other.

---

# Static Members

The `static` keyword means
a member belongs to the class
rather than individual objects.

Example:

```java
class Counter {

    static int count = 0;
}
```

All objects can share
the same static field.

Static methods can be called
using the class name.

Example:

```java
Math.max(10, 20);
```

---

# Final Keyword

The `final` keyword can prevent
further modification.

A final variable cannot
be reassigned after initialization.

A final method cannot
normally be overridden.

A final class cannot
be inherited.

Example:

```java
final double PI = 3.14159;
```

# Exception Handling

Exceptions represent
unexpected or exceptional conditions
during program execution.

Java provides exception-handling mechanisms.

Important keywords include:

* try
* catch
* finally
* throw
* throws

Example:

```java
try {
    int result = 10 / 0;
}
catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero");
}
```

Exception handling helps
applications deal with errors safely.

# Collections

Java provides the Collections Framework
for storing and manipulating groups of objects.

Important collection types include:

* ArrayList
* LinkedList
* HashSet
* TreeSet
* HashMap
* TreeMap

Collections are more flexible
than traditional arrays
for many applications.

---

# ArrayList

ArrayList is a resizable list.

Example:

```java
ArrayList<String> names = new ArrayList<>();

names.add("Ali");
names.add("Ahmad");
names.add("Mosa");
```

Elements can be added or removed
without manually managing
the array size.

---

# HashSet

HashSet stores unique elements.

Example:

```java
HashSet<Integer> numbers = new HashSet<>();

numbers.add(10);
numbers.add(20);
numbers.add(10);
```

The duplicate value
is not stored twice.

HashSet is useful
when uniqueness is important.

---

# HashMap

HashMap stores data
as key-value pairs.

Example:

```java
HashMap<String, Integer> scores = new HashMap<>();

scores.put("Mosa", 90);
scores.put("Ali", 85);
```

A key is used
to retrieve its associated value.

HashMap is useful
for fast key-based lookup.

---

# Generics

Generics allow classes and methods
to work with different types
while maintaining type safety.

Example:

```java
ArrayList<String> names = new ArrayList<>();
```

Here, the collection
is restricted to String values.

Generics reduce the need
for unsafe type casting.

# Four Main Principles of OOP

The four commonly recognized
fundamental principles are:

1. Encapsulation
2. Inheritance
3. Polymorphism
4. Abstraction

These concepts work together
to create flexible
object-oriented software.

---

# Encapsulation in Practice

Encapsulation protects
the internal state of an object.

Instead of directly modifying:

```java
account.balance = -1000;
```

the class can control
the operation through:

```java
account.deposit(500);
```

The class can validate
whether the operation is valid.

---

# Inheritance in Practice

Inheritance allows common behavior
to be placed in a parent class.

Specialized classes
can then extend it.

For example:

```text
Person
├── Student
└── Teacher
```

Common properties belong
to Person.

Specialized behavior belongs
to the subclasses.

---

# Polymorphism in Practice

Polymorphism allows code
to work with general types.

Example:

```java
Animal animal;

animal = new Dog();
animal.sound();

animal = new Cat();
animal.sound();
```

The same reference
can represent different objects.

The behavior changes
according to the actual object.

---

# Abstraction in Practice

Abstraction focuses on
what an object does
rather than how it does it.

A payment system,
for example,
can expose:

```java
payment.process();
```

The user does not need
to understand every internal
payment-processing step.

---

# Object-Oriented Design

Good OOP is not simply
using classes everywhere.

The goal is to create
clear responsibilities
between objects.

Each class should have
a meaningful purpose.

Classes should communicate
through well-designed interfaces.

This makes software easier
to understand and maintain.
